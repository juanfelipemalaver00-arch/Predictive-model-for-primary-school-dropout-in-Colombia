Education Data Integration: Crosswalk & Join Architecture

A technical overview of how the final school-year panel is constructed, which databases are crossed, the keys used at each stage, and how information flows into the final analytical dataset.

1. Executive overview

The pipeline builds a longitudinal school-site × year master panel. The backbone is created from the C-600 "Jornada/Nivel" module using SEDE_CODIGO × PERIODO_ANIO as the primary key. The remaining C-600 modules are attached horizontally with the same key. Null count columns receive 0 (absence of a record means zero students in that category, not missing data). Proportions and vulnerability indices are computed after this fill.

Municipality-level outcomes from SIMAT are aggregated and standardized, then joined through DIVIPOLA which acts as the geographic crosswalk converting names to official five-digit DANE municipality codes. IPM is joined at the region × year level; PDET and ZOMAC are municipality-level binary flags; ICFES is joined at the school-site × year level with a flag TIENE_GRADO_11 indicating whether Saber 11° data exists for that site-year.

4. Source-specific integration logic

C-600: construction of the school-year backbone

The pipeline reads the Jornada/Nivel skeleton for each year 2018–2023. SEDE_CODIGO is standardized to a 12-digit string. Enrollment is converted to numeric; where no explicit total field exists, male and female counts are summed. Records are aggregated to SEDE_CODIGO × PERIODO_ANIO × COD_MPIO_DANE × COD_DPTO_DANE.

All null count columns across the five additional C-600 modules are filled with 0 after the left merge, because the absence of a record means zero students in that category — not missing data. Proportions and the vulnerability index are calculated after this fill.

SIMAT + DIVIPOLA: municipality-level outcomes

SIMAT is restricted to municipality territory and official-sector observations. Names are normalized (upper-case, accent removal, whitespace collapse). Dropout and repetition rates are aggregated to municipality-year as weighted averages using SIMAT TOTAL as the weight. DIVIPOLA provides the crosswalk from standardized names to COD_MPIO_DANE.

For municipalities with no municipal-level rate (primarily Amazonia and Orinoquía departments where SIMAT does not publish disaggregated data), a departmental average fallback is applied. Coverage after corrections: 95.6% at municipal level; 4.4% via departmental fallback; less than 0.1% unresolvable.

IPM: regional context

IPM household files are loaded for each panel year. An important technical detail: files for 2018–2020 use semicolon as the delimiter, while files for 2021–2023 use comma. The pipeline auto-detects the separator. Available deprivation variables are aggregated by region × year using FEX_C as the household weight. All 33 Colombian departments are mapped to one of the 9 official DANE macro-regions. Coverage: 96.7% across all years.

PDET and ZOMAC: municipality enrichment

Both sources provide COD DANE as a 5-digit code. These are matched to COD_MPIO_DANE in the panel producing binary flags. Coverage: 72,484 site-years for PDET (170 municipalities); 110,734 for ZOMAC (344 municipalities).

ICFES: site-level academic performance

ICFES DANE identifiers are normalized to 12-digit strings using zfill(12). The panel school code requires removing the leading 1 prefix before comparison (SEDE_CODIGO[1:]). The match is performed on normalized_site_code × PERIODO_ANIO.

The variable TIENE_GRADO_11 is created as a binary flag: 1 if the site has any ICFES record for that year, 0 otherwise. Coverage is partial by design since only sites with Grade 11 appear in Saber 11° data. The variable ICFES_PCT_CAMPESINA was excluded from the model due to inconsistent reporting across years.

6. Geographic edge cases and resolutions

Fix 1 — Bogotá localities. The C-600 assigns locality codes (11102, 11265, 11279, 11764, 11769, 11848, 11850) to sites within Bogotá, but SIMAT reports a single unified rate under code 11001. All 11xxx codes are remapped to 11001 before the SIMAT join so these sites inherit the Bogotá citywide dropout rate.
Fix 2 — Putumayo legacy code. Some C-600 records carry the legacy code 83 for Putumayo instead of the official DANE code 86. This causes these sites to be invisible to DIVIPOLA and SIMAT. The pipeline remaps COD_DPTO_DANE 83 → 86 and adjusts COD_MPIO_DANE accordingly (83xxx → 86xxx) before any join.
Fix 3 — Amazonia / Orinoquía municipalities. SIMAT does not publish municipal-level rates for very small municipalities in departments such as Amazonas, Vaupés, Guainía, Guaviare and Vichada. These sites receive the departmental average rate as a fallback, computed from all municipalities in the same department and year that do have a valid rate.
Fix 4 — San Andrés / Providencia disambiguation. The name SAN ANDRES appears in three departments (Archipiélago, Santander, Antioquia) and PROVIDENCIA in two (Archipiélago, Nariño). SIMAT records for the Archipiélago are identified by filtering DEPARTAMENTO_STD for the string ARCHIPIELAGO and then renaming those municipalities to unique aliases (SAN ANDRES ISLA, PROVIDENCIA ISLA) before the DIVIPOLA join.
Fix 5 — Cali name mismatch. SIMAT uses the name SANTIAGO DE CALI while DIVIPOLA registers it as CALI. A manual name correction is applied to the SIMAT output before the DIVIPOLA join.
Residual unmatched municipalities (< 0.1%). A small number of municipality codes in the C-600 — primarily new municipalities created after the last DIVIPOLA update and some territorial codes without SIMAT coverage — remain unmatched after all fixes. These sites receive NaN for the target and SIMAT predictors and are documented in the Sin_match_SIMAT sheet of the diagnostic Excel workbook.

8. Validation and quality controls

  • Primary-key validation: duplicate SEDE_CODIGO × PERIODO_ANIO observations trigger an error before export.
  • Period validation: observations outside 2018–2023 trigger an error.
  • Geographic validation: candidate municipality codes are compared with DIVIPOLA, PDET and ZOMAC code sets; mismatches are logged.
  • Coverage diagnostics: coverage reported for SIMAT, IPM, ICFES and selected variables by year and by TRAIN/TEST sample.
  • IPM separator check: the first line of each IPM file is read in binary mode to count commas vs. semicolons and select the correct delimiter automatically.
  • Missingness report: the diagnostic Excel workbook reports null counts, null percentages, means, minima and maxima for all 61 variables.
  • Target diagnostics: Pearson correlations with dropout rate and lag-1 autocorrelation are calculated and printed.
  • Unmatched SIMAT sheet: the workbook contains a dedicated sheet listing site-year observations that received the departmental fallback or remained unmatched.
Train / Test design: 2018–2022 are labelled SAMPLE = TRAIN; 2023 is labelled SAMPLE = TEST. Temporal features (lags, moving averages, deltas) are constructed within each school site after sorting by site and year, so no future information leaks into the training set.
2020 pandemic note: Automatic promotion policies in 2020 suppressed the measured repetition and dropout rates for that year. The FLAG_PANDEMIA variable marks all 2020 observations. A decision on whether to exclude 2020 from the training window is pending advisor review.

9. Final analytical structure

The resulting dataset is organized into 8 logical domains: keys and geography · target variables and temporal lags · enrollment dynamics · C-600 population counts · proportions and vulnerability indices · ICFES performance · IPM regional poverty · PDET/ZOMAC conflict flags.

The final pipeline exports the master panel in both Parquet and CSV formats. The diagnostic workbook contains: completeness by variable, Pearson correlations with the target, coverage by year, TRAIN/TEST coverage, descriptive statistics, unmatched SIMAT observations, and a 2023 test-set sample.
